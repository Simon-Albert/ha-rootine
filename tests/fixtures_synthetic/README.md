# Synthetic fixtures

Generated by `scripts/make_synthetic_fixtures.py` (fixed seed, no real measurements; all times and
amounts are invented). They contain the
patterns the logic has to handle: a sun-driven daily swing, real drying over several days, watering
jumps, a slow rise and a jump after rain, a pulled sensor, reporting gaps of about 30 h, short
`unavailable` phases, valve bursts and test runs without effect, several days of drizzle, frost nights
and a rain gauge that resets at midnight UTC (02:00 local time), with rain shortly before the reset.

Files and formats mirror what the Home Assistant recorder exports (only changes are stored):

| File | Content |
|---|---|
| `plant_a_moisture.csv`, `plant_b_moisture.csv` | `timestamp,state` (%, or `unavailable`) |
| `valve_1.csv`, `valve_2.csv` | `timestamp,state` (`on`/`off`/`unavailable`/`unknown`) |
| `rain_daily.csv` | `date,mm` (daily total per local date) |
| `rain_sensor.csv` | `timestamp,state` (cumulative mm, resets at midnight UTC) |
| `plant_a_temperature_hourly.csv` | `hour_start,mean,min,max` (°C) |

Expected results are computed by the independent oracle `reference.py` in this folder (no code shared
with the integration) and kept as constants in `tests/logic/test_synthetic.py` and `tests/ha/test_replay.py`.

```bash
python -I scripts/make_synthetic_fixtures.py     # regenerate (byte-identical)
python -I tests/fixtures_synthetic/reference.py  # print the expected results
```

If the generator changes, regenerate, rerun the oracle and update the constants from its output, never
from the integration.
